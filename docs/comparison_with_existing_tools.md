# PingEZ の位置づけと今後のアップデート方針

起票日: 2026-05-29  
対象バージョン: v0.1.0 実機検証版

---

## 1. 概要

PingEZ は、閉域 Windows 環境における管理者・ネットワーク担当者向けの、手動実行型ネットワーク疎通確認補助ツールです。  
ping / TCP ポート確認 / tracert / DNS 確認を GUI から手軽に実行し、結果を記録・報告することを目的としています。

本文書では、類似する既製品・既存ツールを参照しながら、以下の点を整理します。

- PingEZ は既製品の代替を目指すものではない
- 既製品は「採用候補」ではなく、**今後の改善を検討する際の設計上の参考**として扱う
- PingEZ の守備範囲と対象外を明確にする

### 既製品を導入しない前提について

既製品のネットワーク確認ツールには優れたものが多数存在します。  
しかし本環境では、セキュリティ・運用の観点から外部製ツールを採用しない方針をとっています。

- 調達・評価・脆弱性管理の負担が生じる
- 閉域環境での動作保証・ライセンス確認が必要になる
- ツールそのものの外部通信・挙動の説明責任が生じる

このため、既製品は「参考」にとどめ、**PingEZ を環境に合わせて育てていく**方針とします。

## 2. 既製品・既存ツールの整理

以下は、PingEZ の改善を検討するうえで参照したツールの整理です。  
いずれも本環境への導入候補ではなく、設計上の参考として位置づけます。

| ツール | 主な用途 | PingEZ への参考可否 | 備考 |
|--------|---------|-------------------|------|
| **ExPing** | 複数宛先への ping 確認・一覧表示 | 参考にしてよい | 一覧性・色分け表示の考え方が参考になる |
| **PingInfoView** | 複数ホストの ping 監視・一覧表示・ログ保存 | 一部参考 | 最終結果一覧・ログ表示の考え方は参考になる。常時監視は対象外 |
| **Advanced IP Scanner** | IP レンジスキャン・端末探索・ポート確認 | 一部参考 | 一覧 UI・ポート名表示の考え方は参考になる。自動探索・スキャン機能は対象外 |
| **PingKeeper** | 継続的な ping 監視・状態記録 | 一部参考 | 状態表示の考え方は参考になる。常時監視・通知機能は対象外 |
| **iperf** | 帯域測定・ネットワーク性能試験 | 参考にしない | PingEZ の目的と異なるため取り込まない |

## 3. PingEZ が参考にしてよい要素

既製品からは、以下の考え方・表示方針を参考にします。  
ただし、すぐに実装するものと将来検討するものに分けます。

### すでに実装済み（v0.1.0 時点）

| 要素 | 内容 |
|------|------|
| 複数宛先の一覧確認 | 宛先入力欄に複数行入力し、まとめて確認できる |
| 色分け表示 | 成功・失敗・タイムアウト・スキップを色で区別 |
| 宛先リストの保存・読込 | TXT ファイルへの保存と読み込みを実装済み |
| ポートサービス名の参考表示 | TCP 確認時に既知ポートのサービス名を付記（参考情報） |
| 結果ログの保存 | TXT / CSV（簡易形式）での保存 |

### 今後参考にしてよい要素（v0.2 系候補）

| 要素 | 参考元 | 内容 |
|------|--------|------|
| 最終結果サマリ | PingInfoView / ExPing | 実行完了後に「成功 N 件 / 失敗 N 件」等を1行でまとめる |
| 列形式 CSV 出力 | Advanced IP Scanner など | 宛先・結果・応答時間を列ごとに分けた集計しやすい形式 |
| 実行結果の簡易フィルタ | PingInfoView | 結果欄の表示を「失敗のみ」などに絞り込む |

## 4. PingEZ に取り込まない要素

以下の機能は、PingEZ の性格・位置づけから外れるため、対象外とします。

| 機能 | 理由 |
|------|------|
| IP レンジスキャン | 自動探索に該当し、FW ログへの誤検知アラームが生じる可能性がある |
| 端末の自動探索 | ネットワーク探索行為として監査・説明が困難になる |
| 常時監視 | 正式な監視システムとの役割分担が曖昧になる |
| 通知機能（アラート等） | 正式な監視システムの役割であり、PingEZ の対象外 |
| 帯域測定 | iperf 等の専用ツールの役割であり、性格が異なる |
| 大量ポートスキャン | セキュリティ上の説明が重くなり、誤解を招くリスクがある |
| 端末情報収集 / MAC アドレス収集 | 調査目的として使われるリスクがあり、確認専用の位置づけから外れる |
| 共有フォルダ探索 | 対象外。認証情報・アクセス制御に関係するため取り込まない |
| 脆弱性診断 | 完全に対象外。セキュリティ評価ツールは別途判断が必要 |
| ネットワーク設定変更 | PingEZ は確認専用であり、設定変更は一切行わない |
| 外部ツール連携 | 閉域環境での外部連携は採用しない |

### 取り込まない理由の整理

上記を対象外とする理由は、以下の観点によります。

1. **セキュリティ上の説明が重くなる**  
   スキャン・探索・帯域測定は、目的・対象・結果の説明責任が生じる。閉域環境の補助ツールとして説明しきれない。

2. **監査・ログ監視上の誤検知につながる可能性がある**  
   IP レンジスキャンや大量ポート確認は FW ログに記録され、セキュリティアラームの誤検知原因になり得る。

3. **正式な監視システムや専用ツールとの役割分担が曖昧になる**  
   常時監視・通知は、SNMP 監視システムやネットワーク管理ツールの役割である。PingEZ が代替することは適切でない。

4. **「確認専用」「手動実行」「軽量補助」という PingEZ の性格から外れる**  
   自動実行・常時監視・探索を含む機能は、補助ツールとしての位置づけを超える。

## 5. PingEZ の守備範囲

### PingEZ で扱う範囲

| 機能 | 内容 |
|------|------|
| Ping 確認 | 指定した宛先への ICMP 疎通確認（成功・失敗・応答時間） |
| TCP ポート確認 | 指定した宛先・ポートへの TCP 接続確認（Open / Refused / Timeout） |
| DNS 確認 | 正引き（ホスト名 → IP）・逆引き（IP → ホスト名） |
| Tracert 確認 | ルート追跡・ホップ IP の逆引き・RTT 色分け |
| 全確認 | Ping / TCP / DNS をまとめて実行 |
| ローカル情報確認 | 実行端末の NIC・IP・ゲートウェイ・DNS サーバの表示 |
| 宛先リスト保存・読込 | 繰り返し使う宛先グループを TXT ファイルで管理 |
| 結果保存 | TXT（推奨）/ CSV（簡易形式）での保存 |
| 色分け表示 | 結果行の内容に応じた色分け |
| ポートサービス名の参考表示 | 既知ポートへのサービス名付記（HTTP, RDP, SMB 等） |

### PingEZ で扱わない範囲

| 機能 | 理由 |
|------|------|
| IP 範囲を指定した探索 | 自動探索に該当するため対象外 |
| 端末の自動発見 | 同上 |
| 常時監視 | 手動実行ツールの位置づけを超えるため対象外 |
| 帯域測定・性能試験 | 専用ツールの役割であり性格が異なる |
| 脆弱性診断 | セキュリティ評価ツールは別途判断が必要 |
| ネットワーク変更 | 確認専用ツールとして設定変更は一切行わない |
| 認証情報を使う処理 | 資格情報の入力・保存機能は含めない |

## 7. 判断基準

今後 PingEZ に機能を追加するかどうかを判断する際は、以下のチェック項目を確認してください。  
すべての項目を満たすことが追加の前提です。

| # | チェック項目 | 補足 |
|---|-------------|------|
| 1 | **確認専用であるか** | ネットワーク設定・端末設定を変更しないこと |
| 2 | **手動実行の範囲に収まるか** | ボタン1クリックで始まり、完了したら終わる処理であること |
| 3 | **ネットワーク探索・スキャンに該当しないか** | IP レンジ探索・自動発見・大量ポート確認を含まないこと |
| 4 | **外部ツールや外部ライブラリを必要としないか** | PowerShell 5.1 標準の範囲で実装できること |
| 5 | **閉域端末で説明しやすいか** | 情報政策課・ネットワーク担当者が「何をしているか」を説明できること |
| 6 | **誤操作時の影響が限定的か** | 誤って実行しても、ネットワーク構成や他端末に悪影響を与えないこと |
| 7 | **結果保存・報告のしやすさに寄与するか** | ベンダー報告・記録用途として役立つこと |
| 8 | **PowerShell 単体 GUI として複雑化しすぎないか** | 単一 .ps1 ファイルで維持できる範囲であること |

## 8. 結論

PingEZ は、既製品より高機能にすることを目指しません。

既製品の優れた点（一覧性・色分け・ログ保存・宛先管理の考え方）を参考にしながら、  
閉域環境で安全に使える、**手動実行型の疎通確認補助ツール**として段階的に改善していきます。

自動探索・常時監視・帯域測定・スキャンといった機能は、説明責任・誤検知リスク・役割分担の観点から対象外とします。  
これらは、既存の監視システムや専用ツールに委ねるべき領域です。

PingEZ の価値は「高機能であること」ではなく、  
**「閉域環境の担当者が、コマンドを知らなくても手軽に確認・記録できること」**にあります。

今後のアップデートは、この位置づけを維持したうえで判断します。
